## What's new

- **The boot partition is read-only while Glovebox runs.** The kernel and firmware sit on the card's boot partition, which used to stay writable the whole time the Pi was on. Now Glovebox opens it only for a moment to save its own files (the setup report, the Wi-Fi country, the encryption recovery files) and closes it again straight after. That greatly reduces the chance that the car cutting the power leaves a Pi that won't start.
- **Updates install the system packages they need.** Before switching over, the update installs anything the new version needs. If that fails, for example because the Pi is offline, the current version keeps running and the update page says why.
- **Skipping versions is fine.** Each release brings the Pi fully up to date, however old the version it replaces.
- **Pis coming from 0.8 or older catch up on their own.** On its first start the new version finishes any package install a power cut interrupted, installs what's missing, and tries again every 15 minutes while it's offline.
- **Room for updates on the drive.** Package installs keep apt's lists and downloads on the drive's storage instead of the system partition, which is too small for them.
- **"Include time at home" now covers kept drives too.** Unchecked, Glovebox already didn't back up what the car recorded at home. Now it doesn't keep those minutes either: preconditioning in a dark garage no longer turns up as black "drives" taking space on the card. Minutes in which the car moved are always kept. Anything already kept that way is cleared after the update.
- **Warnings in the web app.** When something needs your attention, such as boot protection that couldn't be set up or packages that couldn't be installed, a **Needs attention** chip and a note at the bottom of the page say what's wrong.
- **System updates from SSH.** New `glovebox-boot-maintenance` command for kernel and system updates (see Upgrading).

## Fixes

- A power cut while Glovebox saved its settings, its setup report or the encryption recovery files could leave them half-written. They're now written to a new file and swapped in only once they're safely on the card.
- A power cut could empty the records of kept drives and snapshots. Glovebox then started its list of kept drives over and kept minutes it had already skipped as parked. Both records are now written safely.
- After such a reset, footage recorded parked could be kept as a drive when it came before the first drive in a snapshot. Glovebox now reads the whole snapshot before deciding.
- An interrupted encryption header backup could leave no backup at all: the old one was deleted first. It's now kept until the new one is complete.
- Turning on encryption could erase the drive and then fail to save the recovery files: if the boot partition was full or not writable, or the device key was unreadable. All of that is now checked first, and nothing is erased unless it passes.
- Encryption headers now have a fixed size, so the recovery backup always fits in the space checked for it.
- The Wi-Fi country rewrote the boot partition's `cmdline.txt` on every change, even when nothing was different.
- Failures writing to the boot partition (the setup report, a setup reset) were silently ignored. They're now logged.
- `install.sh` stops Glovebox before installing, checks every download against its own entry in `SHA256SUMS` (a missing entry is an error), and still works on older Pis with `/boot` instead of `/boot/firmware`.

## Upgrading

Update from **Settings**. On its first start the new version makes the boot partition read-only, installs `glovebox-boot-maintenance` and keeps the setting for future boots. You don't need to do anything, and nothing needs a reboot.

If you update the system yourself over SSH (`apt full-upgrade`, kernel or firmware), run it through the new command, because the boot partition is now read-only:

```sh
sudo glovebox-boot-maintenance --protect bash -c 'apt-get update && apt-get full-upgrade'
```

Do this on a stable power supply, not the car's USB port. Details: [Power loss and read-only boot maintenance](https://github.com/lubaxe/glovebox/blob/main/docs/power-loss.md).

The read-only boot partition reduces the risk of a damaged kernel; it doesn't remove it, and the cause of the one case reported is still unknown. Keep a spare card or a backup image.
